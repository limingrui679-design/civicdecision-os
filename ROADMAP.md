# Roadmap

The roadmap separates software delivery from evidence that depends on independent people or
institutions. A checked item means the repository contains inspectable completion evidence; it
does not imply municipal adoption or real-world impact.

## Public product path

- [x] Publish a read-only, claim-bounded guided walkthrough.
- [x] Put a five-minute quickstart and golden case before the technical inventory.
- [x] Add a documentation build with three task-oriented tutorials.
- [ ] Publish a Python package through a configured trusted PyPI publisher.
- [ ] Add a second guided case from an independently selected public dataset.

## External verification path

- [x] Publish a reviewer protocol and reproducibility issue form.
- [ ] Record one independent clean-environment reproduction of the Suffolk reference pair.
- [ ] Record one urban-domain review of source semantics, assumptions, and prohibited claims.
- [ ] Resolve or explicitly retain every finding from the first external review round.
- [ ] Archive a reviewed release and method note with a DOI.

No reviewer is currently assigned in this repository, and no unchecked item should be described
as completed.

## Contributor path

- [x] Add issue and pull-request evidence templates.
- [x] Add a code of conduct, citation metadata, and a public roadmap.
- [ ] Label and mentor the first three accepted `good first issue` contributions.
- [ ] Add one independently maintained data-only adapter package.
- [ ] Document a stable deprecation policy before the first non-alpha release.

## Governance and security path

- [x] Document the threat model, release assurance, and private disclosure route.
- [ ] Complete an independent security review of the local API and release pipeline.
- [ ] Define an artifact-signing and key-rotation policy before signed releases are claimed.
- [ ] Define production authentication, authorization, privacy, retention, and incident-response
  requirements before any hosted analytical service is claimed.
